# 🌐 Introduction to Networking

> *"To hack a network, you must first understand it."*

---

## 1. What is a Network?

A **computer network** is a system of interconnected devices that can communicate and share resources with each other. These devices can be computers, smartphones, printers, servers, or any smart device.

Networks allow us to:
- Share files and resources (printers, storage)
- Communicate (email, chat, video calls)
- Access the internet
- Run distributed applications

### Key Terminology

| Term | Definition |
|------|-----------|
| **Node** | Any device connected to a network |
| **Host** | A node that sends or receives data |
| **Server** | A host that provides services or resources |
| **Client** | A host that requests services |
| **Bandwidth** | Maximum data transfer rate (e.g., 100 Mbps) |
| **Latency** | Time delay for data to travel from source to destination |
| **Protocol** | A set of rules governing how data is transmitted |
| **Topology** | The physical or logical layout of a network |

## 2. Types of Networks

![Image Description|527](https://i.imgur.com/0IMTzlj.png)
Networks are classified by their **geographic scope** and **scale**. Here's a breakdown from smallest to largest:

---

### 🔵 PAN — Personal Area Network

- **Range:** ~10 meters (a single person's space)
- **Purpose:** Connect personal devices around an individual
- **Examples:** Bluetooth headset ↔ phone, smartwatch ↔ laptop, wireless keyboard ↔ PC
- **Technologies:** Bluetooth, Zigbee, Infrared (IrDA), NFC

```
[Laptop] <--Bluetooth--> [Headphones]
[Phone]  <--NFC-------> [Smartwatch]
```


---

### 🟢 LAN — Local Area Network

- **Range:** Up to ~1 km (a building or campus)
- **Purpose:** Connect devices within a limited area — home, office, school lab
- **Examples:** Your home Wi-Fi, a university lab network, an office floor network
- **Technologies:** Ethernet (IEEE 802.3), Wi-Fi (IEEE 802.11), Switches, Routers

```
[PC1] ---+
[PC2] ---+--- [Switch] --- [Router] --- Internet
[PC3] ---+
```

**Key LAN devices:**
- **Switch:** Connects devices within the same LAN, forwards frames using MAC addresses
- **Router:** Connects the LAN to other networks (like the internet), uses IP addresses
- **Access Point (AP):** Extends LAN wirelessly

---

### 🟡 MAN — Metropolitan Area Network

- **Range:** A city or metropolitan area (~10–100 km)
- **Purpose:** Connect multiple LANs within a city
- **Examples:** City-wide ISP infrastructure, cable TV networks, municipal Wi-Fi
- **Technologies:** Fiber optic, WiMAX (IEEE 802.16), SONET/SDH

```
[Office LAN] ---+
[University  ] ---+--- [MAN Backbone] --- [City ISP]
[Hospital LAN] ---+
```

---

### 🔴 WAN — Wide Area Network

- **Range:** Countries or continents (unlimited)
- **Purpose:** Connect networks across large geographic distances
- **Examples:** The Internet (the world's largest WAN), corporate VPN connections between offices
- **Technologies:** MPLS, leased lines, satellite links, submarine fiber cables

> The **Internet** is essentially a massive WAN made up of millions of interconnected LANs and MANs.

---

### 🟠 Other Network Types (Quick Overview)

| Type | Full Name | Scope | Use Case |
|------|-----------|-------|----------|
| **WLAN** | Wireless LAN | Local | Wi-Fi in a building |
| **SAN** | Storage Area Network | Local | High-speed access to storage devices |
| **VPN** | Virtual Private Network | Any | Secure tunnel over public networks |
| **CAN** | Campus Area Network | Campus | University/corporate campus |
| **GAN** | Global Area Network | Global | Satellite-based global connectivity |

## 3. The OSI Model

### What is the OSI Model?

The **Open Systems Interconnection (OSI) model** is a conceptual framework developed by the **ISO (International Organization for Standardization)** in 1984. It standardizes the communication functions of a network into **7 distinct layers**.

**Why does it matter?**
- Gives us a common language to describe network operations
- Helps troubleshoot network issues (isolate problems to a specific layer)
- Allows different vendors' equipment to interoperate
- Essential for understanding cybersecurity attacks (most attacks target a specific layer)

---

![OSI](https://i.imgur.com/AGmYavk.png)

### The 7 Layers at a Glance

```
┌─────────────────────────────────────────────┐
│  Layer 7 — Application   │  HTTP, FTP, DNS  │  ← Closest to the user
├─────────────────────────────────────────────┤
│  Layer 6 — Presentation  │  SSL, JPEG, ASCII│
├─────────────────────────────────────────────┤
│  Layer 5 — Session       │  NetBIOS, RPC    │
├─────────────────────────────────────────────┤
│  Layer 4 — Transport     │  TCP, UDP        │
├─────────────────────────────────────────────┤
│  Layer 3 — Network       │  IP, ICMP        │
├─────────────────────────────────────────────┤
│  Layer 2 — Data Link     │  Ethernet, MAC   │
├─────────────────────────────────────────────┤
│  Layer 1 — Physical      │  Cables, Signals │  ← Closest to hardware
└─────────────────────────────────────────────┘
```

**Memory trick:** *"All People Seem To Need Data Processing"* (top to bottom: Application, Presentation, Session, Transport, Network, Data Link, Physical)

Or bottom to top: *"Please Do Not Throw Sausage Pizza Away"*

## 4. Deep Dive: Each OSI Layer

---

### Layer 1 — Physical Layer ⚡

**Role:** Transmits raw **bits (0s and 1s)** over a physical medium.

**What it does:**
- Defines the physical characteristics of the network: cables, connectors, voltage levels, pin layouts, wireless frequencies
- Converts data into electrical signals, light pulses (fiber), or radio waves (Wi-Fi)
- No awareness of the meaning of data — just raw signal transmission

**Key components:**
- Cables: Ethernet (Cat5e, Cat6), Fiber Optic, Coaxial
- Hubs (dumb repeaters — broadcast everything)
- Wireless antennas and radio frequencies (2.4 GHz, 5 GHz)
- Repeaters and signal amplifiers

**Data unit:** **Bit**

> **Cybersecurity relevance:** Physical layer attacks include cable tapping, hardware keyloggers, and signal jamming.

---

### Layer 2 — Data Link Layer 🔗

**Role:** Provides **node-to-node** data transfer and handles error detection on the physical link.

**What it does:**
- Packages raw bits into **frames**
- Assigns and uses **MAC (Media Access Control) addresses** to identify devices on the same network
- Handles error detection (but not correction) using CRC (Cyclic Redundancy Check)
- Controls how devices share the physical medium (CSMA/CD for Ethernet)

**Two sub-layers:**
- **LLC (Logical Link Control):** Manages flow control and error checking
- **MAC (Media Access Control):** Handles addressing and channel access

**Key components:**
- Switches (learn and use MAC addresses)
- Network Interface Cards (NICs)
- ARP (Address Resolution Protocol — maps IP → MAC)

**Data unit:** **Frame**

---

### Layer 3 — Network Layer 🌐

**Role:** Handles **logical addressing** and **routing** of data between different networks.

**What it does:**
- Assigns **IP addresses** to devices (IPv4: 32-bit, IPv6: 128-bit)
- Routes packets from source to destination across multiple networks
- Determines the best path using routing protocols (OSPF, RIP, BGP)
- Handles packet fragmentation and reassembly

**Key components:**
- Routers
- IP (Internet Protocol): IPv4, IPv6
- ICMP (Internet Control Message Protocol — used by `ping`)
- Routing protocols: RIP, OSPF, BGP

**Data unit:** **Packet**

**Example IP packet structure:**

```
[ Source IP | Destination IP | TTL | Protocol | Payload ]
```


---

### Layer 4 — Transport Layer 🚚

**Role:** Provides **end-to-end communication** between applications, handling reliability and flow control.

**What it does:**
- Segments data from the session layer into smaller chunks
- Ensures complete data transfer (with TCP) or fast transfer (with UDP)
- Manages **ports** to identify which application data belongs to
- Handles flow control, error recovery, and congestion control

**The two main protocols:**

| Feature | TCP | UDP |
|---------|-----|-----|
| Connection | Connection-oriented (3-way handshake) | Connectionless |
| Reliability | Guaranteed delivery | No guarantee |
| Speed | Slower | Faster |
| Use cases | HTTP, FTP, SSH, Email | DNS, video streaming, VoIP, gaming |
| Error checking | Yes (retransmission) | Basic checksum only |

**TCP 3-Way Handshake:**
```
Client ──── SYN ────────────► Server
Client ◄─── SYN-ACK ───────── Server
Client ──── ACK ────────────► Server
          [Connection Established]
```

**Common ports to know:**

| Port | Protocol | Service |
|------|----------|---------|
| 22 | TCP | SSH |
| 23 | TCP | Telnet |
| 25 | TCP | SMTP (email) |
| 53 | UDP/TCP | DNS |
| 80 | TCP | HTTP |
| 443 | TCP | HTTPS |
| 3389 | TCP | RDP |

**Data unit:** **Segment** (TCP) / **Datagram** (UDP)

---

### Layer 5 — Session Layer 🤝

**Role:** Manages **sessions** (connections) between applications.

**What it does:**
- Establishes, maintains, and terminates communication sessions
- Synchronizes data exchange and manages dialogue control (who talks when)
- Provides checkpointing for long transfers (so you can resume if interrupted)

**Examples:**
- NetBIOS (Windows networking)
- RPC (Remote Procedure Call)
- PPTP (Point-to-Point Tunneling Protocol)
- SAP (Session Advertisement Protocol)

**Data unit:** **Data**

---

### Layer 6 — Presentation Layer 🎨

**Role:** Translates data between the application layer and the network — the **translator** of the OSI model.

**What it does:**
- **Encoding/Decoding:** Converts data to a standard format (e.g., ASCII, Unicode)
- **Encryption/Decryption:** Secures data (e.g., TLS/SSL encryption happens here)
- **Compression/Decompression:** Reduces data size for faster transfer
- Ensures data from one system can be read by another (format translation)

**Examples:**
- SSL/TLS (encryption for HTTPS)
- JPEG, PNG, GIF (image formats)
- MPEG, MP4 (video formats)
- ASCII, Unicode (text encoding)

**Data unit:** **Data**

---

### Layer 7 — Application Layer 💻

**Role:** The layer **closest to the end user** — provides network services directly to user applications.

**What it does:**
- Provides the interface between the network and the user's software
- Defines protocols for specific types of communication
- Does NOT include the applications themselves (Chrome, Firefox) — just the protocols they use

**Key protocols:**

| Protocol | Purpose |
|----------|---------|
| **HTTP/HTTPS** | Web browsing |
| **FTP/SFTP** | File transfer |
| **SMTP/IMAP/POP3** | Email sending/receiving |
| **DNS** | Domain name → IP resolution |
| **DHCP** | Automatic IP address assignment |
| **SSH** | Secure remote access |
| **SNMP** | Network device management |
| **Telnet** | Insecure remote access |

**Data unit:** **Data / Message**
---

### OSI Model Summary Table

| Layer | Name         | Data Unit        | Key Protocols              | Key Devices             |
| ----- | ------------ | ---------------- | -------------------------- | ----------------------- |
| 7     | Application  | Data             | HTTP, DNS, FTP, SMTP       | Firewalls (L7), Proxies |

## 5. Data Encapsulation
![Encapsulation](https://i.imgur.com/wRtYuBl.png)
### What is Encapsulation?

**Encapsulation** is the process by which each OSI layer **adds its own header (and sometimes trailer)** to the data received from the layer above before passing it down to the next layer.

Think of it like putting a letter in envelopes:
- Your letter → put in an inner envelope (with recipient's name)
- Inner envelope → put in an outer envelope (with full address)
- Outer envelope → put in a shipping box (with routing label)

Each layer wraps the data with its own addressing/control information.

---

### Encapsulation Step by Step

```
APPLICATION LAYER
┌─────────────────────────────┐
│         DATA (Message)      │    ← e.g., HTTP request
└─────────────────────────────┘
              ↓ Layer 4 adds TCP/UDP header
TRANSPORT LAYER
┌──────────┬──────────────────┐
│TCP Header│      DATA        │    ← Now called a SEGMENT
└──────────┴──────────────────┘
              ↓ Layer 3 adds IP header
NETWORK LAYER
┌─────────┬──────────┬────────┐
│IP Header│TCP Header│  DATA  │    ← Now called a PACKET
└─────────┴──────────┴────────┘
              ↓ Layer 2 adds Frame header + trailer
DATA LINK LAYER
┌──────┬─────────┬──────────┬────────┬──────┐
│Frame │IP Header│TCP Header│  DATA  │ FCS  │    ← Now called a FRAME
│Header│         │          │        │      │
└──────┴─────────┴──────────┴────────┴──────┘
              ↓ Layer 1 converts to bits
PHYSICAL LAYER
  01001011 10110100 11001010 ...       ← Raw BITS on the wire
```

**FCS** = Frame Check Sequence (error detection trailer)

---

### De-Encapsulation (Receiving Side)

When data arrives at the destination, the **reverse process** occurs:
- Each layer **removes** its own header and passes the data up
- Layer 1 → 2 → 3 → 4 → 5 → 6 → 7, unwrapping at each step
- The final application receives the original data

---

### Why Encapsulation Matters

Each header added during encapsulation contains information that can be:
- **Inspected** by network security tools (IDS/IPS, firewalls)
- **Spoofed** by attackers (IP spoofing, ARP spoofing)
- **Analyzed** by Wireshark to understand network traffic

Understanding encapsulation is fundamental to understanding how attacks like **man-in-the-middle**, **packet injection**, and **protocol fuzzing** work.
